# Autenticación y operación
El runtime no crea cuentas. Acceso local apagado por defecto. No existe registro público, contraseña predeterminada ni recuperación ficticia.
OIDC: registrar cliente confidencial en Entra ID/ADFS compatible. Infraestructura debe entregar issuer HTTPS, client ID, secreto mediante gestor autorizado y callback exacto APP_ORIGIN/api/auth/callback. Requerir MFA mediante política del IdP y verificar emisión amr=mfa. La adaptación a un acr corporativo diferente requiere revisión explícita.
Aprovisionar primera identidad: npm run admin:provision -- "issuer" "subject" "Nombre" desde cuenta instaladora autorizada. El comando verifica issuer, transacción y marca irreversible de bootstrap; no es endpoint. Obtener subject validado de Infraestructura, no inferirlo del correo. Requiere MFA. Ningún nombre de rol concede permisos implícitos.
El primer administrador local de desarrollo puede aprovisionarse con npm run admin:local y ejecutar su SQL privado en SSMS. Requiere confirmar MFA y cambiar la contraseña inicial antes de recibir sesión. Las altas ordinarias, recuperación y producción siguen pendientes; ver docs/deployment/local-admin.md.
Cambio inicial y enrolamiento TOTP local implementados. Recuperación, cambio posterior de contraseña, comprobación completa de contraseñas comprometidas, reautenticación y reevaluación periódica corporativa pendientes. No activar cuentas locales de producción antes de completarlos.
Logout y revoke-all invalidan sesiones SQL. Un IdP deshabilitado no se consulta en cada petición: duración máxima 12h (inactividad 15 min); añadir revocación back-channel o comprobación corporativa según políticas.
